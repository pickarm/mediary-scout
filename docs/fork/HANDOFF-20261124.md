以下为首审发现的问题及当前代码修复情况，仍须由独立审核确认。服务与执行器修复的开发者报告为：服务/命令46项、五类transfer回归296项、光鸭协议97项通过；不能用这些报告替代main集成或最终全仓结果。

| 边界 | 当前修复 | 接手验收重点 |
|---|---|---|
| 落地区派生写权限 | main先从所选电影根回读目录ID与任务目录名，再为123/天翼/光鸭重建授权范围 | 连续prepare→submit；验证真实执行器范围规则；保留115/夸克原保护 |
| 内部与provider回执 | 服务保留`kind=direct_link_transfer`，原类型写入`providerKind` | provider原始kind不能覆盖内部kind；重启可还原查询 |
| 完成证据 | 只有`receipt.state=completed`进入扫描 | `status=succeeded`但缺state时仍待核实 |
| 提交前崩溃 | `intent/landing_ready`可继续；外部调用前先保存`submitting` | 已提交或未知结果只查询，不能重复提交 |
| 停止 | 覆盖direct_pending、提交前、扫描后及识别批次间；扫描返回后服务重读停止标志 | 提交前不产生远端任务；扫描期间停止后不启动新识别整理 |
| 光鸭离线状态 | 按现有契约映射1运行、2完成、3失败，其余未确认状态unknown | 正常运行不能误报失败 |
| 字幕及部分整理 | 任一跳过文件使整理为partial，服务不刷新partial | 未配对字幕留原位；状态如实；语言/forced保留 |
| 刷新载荷 | main从真实绑定读取作品、TMDB、类型、年份和集号 | Webhook不能把provider文件ID当集号；只刷新核实的新视频 |
| 链接与提取码 | 去中文句末标点；URL外提取码写入candidate密码字段 | 常见中文粘贴、URL内外密码、六品牌及磁力兼容 |
| 刷新崩溃 | 服务先写`refresh_pending/refreshStartedAt` | 未知结果不自动重复刷新，报告unknown，不伪称已刷新 |

`submitting`采用避免重复远端任务的取舍：若刚写标记但请求尚未到达provider时崩溃，恢复也不会自动重提。刷新标记同理，可能报告unknown而不补发。这些限制应在最终交付中保留说明。
