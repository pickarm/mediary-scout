## 三、已知行为取舍与外部未验证项

### 1. 已知保守设计取舍
- **`stage=submitting` 崩溃窗口**：外部提交前先持久化 `submitting`。若进程恰好在写库后、请求未抵达网盘前退出，恢复仅走查询/回读，不自动重新 `transfer`，以避免造成重复远端任务。
- **`stage=refresh_pending` 崩溃窗口**：调用媒体服务器刷新前先持久化 `refresh_pending` 与 `refreshStartedAt`。若发出 HTTP 前退出，恢复标记 `refreshStatus="unknown"` 且不自动重发，保持 at-most-once 语义。

### 2. 未验证的外部项（须于独立实测/发布前补充）
- **既有 6 个库管理浏览器测试**（`apps/web/components/library-*.browser.test.ts`，共 25 项）：本轮未改动对应库管理界面组件，在非 PG 全仓运行中按开关跳过（需独立预置预览会话服务）；上一基线运行记录为 25/25 通过，本轮仅重新实测了消息设置浏览器测试 2/2。
- **真实消息平台**：个人微信（iLink 扫码/PIN/私聊）、飞书长连接与卡片、Telegram 长轮询与按钮均仅以协议/SDK 双验证，未连接真实平台收发。
- **真实六大网盘**：115、夸克、UC、123、天翼、光鸭的真实账号登录态、目录分页、转存/离线磁力时序、字幕跟随与落盘一致性均未在独立真实测试目录实测。
- **真实媒体服务器与 Webhook**：Emby / Jellyfin / Plex / 自定义 Webhook 仅验证了请求载荷与错误处理，未连接真实服务器。
- **生产切换与镜像发行**：正式 PostgreSQL 备份/恢复/切换及本版 `amd64` 镜像构建推送均未执行。
