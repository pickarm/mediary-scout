# 巡影 Fork 首版 PRD

状态：实施中。日期：2026-11-14。需求负责人：主代理。

## 目标
让已有光鸭电影和剧集被巡影管理；统一命名；让不访问网盘的步骤提前并发；解决媒体库和队列随规模增长而卡顿的问题。NAS 直接拉取镜像运行。

## 用户与边界
主要用户为已有 Docker 巡影实例的个人 NAS 用户。目标 linux/amd64，外部 PostgreSQL、Redis、PanSou，一个巡影应用容器。
保留原生黑灰底、绿色强调色和现有组件风格，布局可调整。暂不加入自定义画质择优、微信/飞书/TG、手动选源或桌面发行。

## 功能需求
| 编号 | 能力 | 预期行为与验收 |
|---|---|---|
| SCAN-01 | 选择目录 | 选择一个或多个光鸭源目录及电影/剧集/混合类型；指定整理目标；不能越过授权根操作其他文件。 |
| SCAN-02 | 遍历与恢复 | 分页、嵌套遍历；手动与定时执行；暂停/继续/取消；重启保留检查点；部分失败不冒充全量成功。 |
| ID-01 | 识别 | 文件、目录、年份、集号、TMDB 标记优先；困难项可由 AI 提出候选并由 TMDB 验证；不可靠项目不写盘，列为待确认。 |
| IMPORT-01 | 导入 | 不论资源来源，建立作品、季集、真实文件与目录关联；重复扫描不产生重复副本或转存记录。 |
| TRACK-01 | 补缺 | 显示缺集；扫描导入新作品补缺默认关闭；现有追更状态保持不变。身份确认不等于手动选择下载资源。 |
| NAME-01 | 模板 | 分别设置电影目录/文件、剧集目录/季目录/文件模板，提供预览；非法字段和越界路径被拒绝。后续获取使用同一模板。 |
| ORGANIZE-01 | 整理 | 符合规则的文件跳过；高置信度自动执行改名/移动；保留多版本，碰撞不覆盖；字幕跟随视频并保留语言标记。 |
| ORGANIZE-02 | 可恢复 | 持久化操作清单，执行后回读确认，超时先核实现场；失败可重试但不重复写盘。 |
| PREP-01 | 提前准备 | 同盘五部作品可以提前准备；搜索/AI分别限流；取消或终态任务不继续准备；最终获取仍核实实际文件。 |
| PERF-01 | 库与队列 | 服务端分页、筛选与聚合；列表不加载全量日志和全集数据；海报缺失不阻塞；单页面共享进度连接。 |
| REDIS-01 | 加速与降级 | 热点摘要/进度/唤醒使用 Redis；缓存按账号/网盘/媒体类型隔离；Redis 清空或断开不丢任务。 |
| RELEASE-01 | 镜像 | CI 构建 amd64 镜像发布 Docker Hub；NAS只拉取，不构建；版本来源指向 Fork。 |
| MIGRATE-01 | 兼容 | 备份与数据库副本演练；保留作品、任务、连接、设置与追更行为；正式切换仅一套实例有写权限。 |

## 默认值与限制
- 准备并发 5，单 PanSou 服务 2，AI 2；均可配置，属于初始设置，不是实测容量。
- 自动补缺默认关闭。多版本默认保留。定时扫描由用户启用和选择时间。
- 电影默认 `{title} ({year})/{title} ({year}){ext}`；剧集默认 `{title} ({year})/Season {season:02}/{title} - {episodeCode}{ext}`。
- 扫描只依据可获取证据识别，不能保证从毫无信息的文件名判断内容。不下载整部视频进行识别。
- 180 部为示例场景，不代表用户实际库规模。性能比较使用固定测试数据和相同环境。

## 发布门槛
模块测试、原有回归、PG/Redis集成、web构建、镜像检查、数据迁移演练和独立光鸭目录验证均需有证据。缺少环境时明确列出待验证项，不能称为生产验收通过。
